# v0.2.0 — 企业证据闭环、指标底座与混合检索

发布日期：2026-09-02

[中文](#中文) | [English](#english)

## 中文

`v0.2.0` 是从“可运行论文 RAG”走向“证据约束产学研方案”的第二个功能版本。它合并了企业端 P1 核心闭环、论文方向与性能指标底座，以及工作包 7 的可消融混合检索。

本版本仍是本地单机原型。真实论文、企业需求、向量数据库、指标记录、评测运行文件和 API Key 均不包含在 Release 中。

### 主要更新

#### 1. 企业端 P1 核心闭环

- 将企业原话拆成业务目标、产品/对象、问题、科研能力、量化指标、测试条件、已有基础、排除路线和未解析片段。
- 所有解析字段保留企业原句来源；系统未知项不会伪装成企业需求。
- 网页支持逐字段修改、保存不可覆盖 JSON 版本、恢复历史版本和确认冻结。
- 只有已保存并确认的版本才能进入重型检索和方案生成。
- 按技术模块分别检索论文与教师证据；没有证据的模块明确标注缺口。
- 方案数量由证据覆盖闸门决定，不固定凑出三个方案。
- 输出技术路线、四维已知项转化评估、五项硬门槛、分阶段落地计划、验收/退出条件、Markdown 报告和原生可编辑 `.drawio`。
- 增加带公开来源、明确标注“非委托”的江西电缆量化验收案例。

#### 2. 研究方向与指标底座

- 方向分类采用“人工元数据优先 → 关键词规则 → 可选模型兜底 → `unclassified`”。
- 每篇方向记录保留来源、置信度、命中词和人工复核状态。
- 第一版指标本体覆盖 13 个 X 射线/光电探测高频指标。
- 支持别名、单位字形归一和显式单位换算。
- 指标记录保留原文值、点值/区间、规范值、测试条件、页码、章节、Chunk、原文摘录和 `measured/reported/inferred`。
- 无条件或测试条件不同的数据不会被直接判为可比。
- 本地 3 篇、894 个 Chunk 共生成 160 条可定位指标记录；这些派生记录由 Git 忽略。

#### 3. 工作包 7：统一过滤与混合检索

- 为 Dense、BM25、RRF 和可选 CrossEncoder 使用同一候选过滤契约。
- 支持方向、章节和规范数值硬筛。
- 数值阈值先按指标本体换算；默认不把 `inferred` 当作已达到的硬指标。
- 多指标约束按 AND 处理；区间必须整体满足门槛，不能只取有利端点。
- 内置中英混合技术文本 BM25，不增加额外依赖。
- 使用 Reciprocal Rank Fusion 融合 Dense 与 BM25，并保留组成名次。
- 提供可选 sentence-transformers CrossEncoder 适配器；重排模型不随 Release 下载，必须显式选择。
- 每种方法保存独立 run 文件，避免只展示最终方案而无法复查消融过程。

#### 4. 可重复的检索实验清单

- `manifest.json` 保存查询文件 SHA-256、向量集合版本、Top-K、候选数、RRF 参数、过滤查询数和设备。
- 每种方法分别记录平均、P50、P95、最大延迟和峰值 CUDA 显存。
- 多种方法使用独立检索引擎实例，避免缓存让后一方法虚假变快。
- 提供人工 qrels 后，所有方法在同一份标注上自动生成 Recall@5/10、MRR@5/10、nDCG@5/10 和逐问题结果。
- 未提供人工 qrels 时，manifest 明确写入 `no_human_qrels`，不发布虚假的“准确率提升”。

### 本地验收

- 117 项离线测试全部通过。
- Python 编译检查通过。
- 3 篇本地论文、894 个 Chunk、4 条工程烟测查询。
- Dense、BM25、RRF 均成功生成独立 run；Chunk ID 无重复。
- 灵敏度 `>= 1000 μC Gy_air^{-1} cm^{-2}` 的数值硬筛得到 7 个候选，三种方法均未越界返回。
- 本机 CUDA 烟测 P50：Dense `7.094 ms`、BM25 `13.573 ms`、RRF `20.900 ms`。
- BM25 不使用 GPU；Dense/RRF 峰值 CUDA 分配约 `101.384 MB`。

上述时间只用于本机工程烟测，查询数很少，不代表规模化性能。由于尚未建立人工 qrels，本版本不声称 RRF 的召回质量已经超过 Dense。

### 使用方法

安装或升级依赖后，双击：

- `启动网页Demo.cmd`；或
- `Start-Web-Demo.cmd`。

运行工作包 7 消融实验：

```powershell
conda activate industry_agent
python scripts/run_retrieval_eval.py `
  --queries data/evaluation/queries.jsonl `
  --qrels data/evaluation/qrels.jsonl `
  --output-dir data/evaluation/runs/experiment-001 `
  --methods dense bm25 rrf
```

查询过滤格式示例见 `examples/retrieval_queries.sample.jsonl`。

### 数据与安全边界

GitHub 自动生成的 ZIP/tar.gz 只包含代码、配置、合成/公开示例、测试和文档。以下内容继续由 `.gitignore` 排除：

- `.env` 与 Moonshot API Key；
- 真实 PDF 和本地 ChromaDB；
- 指标记录、能力记录、教师画像；
- 企业需求版本、匹配结果、Agent 运行记录；
- 查询、qrels、run、manifest 等本地评测数据；
- 下载的 Embedding/CrossEncoder 模型缓存。

### 已知限制

- 真实检索质量仍需人工核页制作 qrels 后才能量化。
- CrossEncoder 适配器已经实现，但本版本不捆绑或默认下载重排模型。
- 指标抽取当前是确定性规则通道；复杂并列关系和语义补充仍待人工复核或后续可选模型通道。
- 当前 PDF 管线不解释论文图片、复杂表格或扫描页 OCR。
- 院校端论文精读工作台、PDF 报告和论文谱系图属于后续工作包。
- 当前仍是本地单用户应用，不含账号、多租户隔离或公网部署。

## English

`v0.2.0` moves the project from a runnable paper-RAG prototype toward an evidence-gated industry–academia solution workflow. It combines the P1 enterprise loop, research-direction and performance-metric foundations, and the Work Package 7 hybrid-retrieval stack.

This is still a local single-machine prototype. Real papers, enterprise requests, vector databases, metric records, evaluation runs, and API keys are not included in the release.

### Highlights

#### 1. P1 enterprise evidence loop

- Decomposes original enterprise wording into goals, objects/products, problems, research capabilities, numeric targets, test conditions, existing foundations, excluded approaches, and unparsed fragments.
- Every parsed field retains its source wording; unknowns are never presented as enterprise claims.
- Supports field-level editing, immutable local JSON snapshots, history restore, and confirmation freeze.
- Heavy retrieval and solution generation only run from a saved, confirmed version.
- Retrieves paper and teacher evidence per technical module and exposes evidence gaps.
- Solution count is evidence-gated rather than padded to three alternatives.
- Produces a technical route, known-only four-dimension transfer assessment, five hard gates, phased landing plan, acceptance/exit criteria, Markdown report, and native editable `.drawio`.
- Includes a sourced public Jiangxi Cable acceptance case explicitly labeled as not being a client engagement.

#### 2. Direction and metric foundations

- Direction routing follows metadata → keyword rules → optional model fallback → `unclassified`.
- Each assignment records source, confidence, matched terms, and review state.
- The first ontology covers 13 high-frequency X-ray/optoelectronic metrics.
- Supports aliases, typographic unit normalization, and explicit conversions.
- Metric evidence retains the raw value, point/range form, canonical value, test condition, page, section, chunk, quote, and `measured/reported/inferred` level.
- Records with missing or different test conditions are not declared directly comparable.
- The local three-paper/894-chunk audit produced 160 traceable records; derived records remain Git-ignored.

#### 3. Work Package 7 hybrid retrieval

- One candidate-filter contract for Dense, BM25, RRF, and optional CrossEncoder reranking.
- Direction, section, and canonical numeric hard filters.
- Numeric thresholds are normalized through the ontology; `inferred` is excluded from hard claims by default.
- Multiple metric constraints use AND semantics, and ranges must satisfy the full threshold.
- Dependency-free BM25 for mixed Chinese/English technical text.
- Reciprocal Rank Fusion over Dense and BM25 with component ranks retained.
- Optional sentence-transformers CrossEncoder adapter; no reranker model is bundled or downloaded by default.
- Independent run files for every method so ablations remain inspectable.

#### 4. Reproducible experiment manifests

- Query-file SHA-256, vector-collection version, Top-K, candidate size, RRF settings, filter count, and device are recorded.
- Mean, P50, P95, max latency, and peak CUDA memory are recorded per method.
- Methods use fresh retrieval-engine instances so cache warm-up cannot make later methods look artificially faster.
- With human qrels, every method automatically produces Recall@5/10, MRR@5/10, nDCG@5/10, and per-query results against the same judgments.
- Without human qrels, the manifest explicitly records `no_human_qrels` and makes no retrieval-quality claim.

### Local acceptance

- All 117 offline tests passed.
- Python compile checks passed.
- Three local papers, 894 chunks, and four engineering smoke-test queries.
- Dense, BM25, and RRF produced independent duplicate-free runs.
- A sensitivity hard filter of `>= 1000 μC Gy_air^{-1} cm^{-2}` yielded seven eligible chunks; no backend returned an out-of-filter chunk.
- Local CUDA P50 smoke timings: Dense `7.094 ms`, BM25 `13.573 ms`, RRF `20.900 ms`.
- BM25 used no GPU; Dense/RRF peak CUDA allocation was approximately `101.384 MB`.

These timings are local engineering smoke measurements over a very small query set, not scale benchmarks. Human qrels do not exist yet, so this release does not claim that RRF retrieval quality exceeds Dense.

### Data and security boundary

GitHub's generated ZIP/tar.gz contains only code, configuration, synthetic/public examples, tests, and documentation. `.gitignore` continues to exclude:

- `.env` and Moonshot API keys;
- real PDFs and local ChromaDB data;
- metric/capability records and teacher profiles;
- enterprise versions, match outputs, and Agent runs;
- local queries, qrels, runs, and experiment manifests;
- downloaded embedding or CrossEncoder model caches.

### Known limitations

- Real retrieval quality still requires page-checked human qrels.
- The CrossEncoder adapter is implemented, but no reranker is bundled or downloaded by default.
- Metric extraction currently uses deterministic rules; complex enumerations and semantic supplementation need human review or a later optional model channel.
- Figures, complex tables, and scanned-page OCR are not interpreted yet.
- The academic paper workbench, PDF reports, and paper lineage graph remain future work packages.
- The application is still local and single-user, without accounts, multi-tenant isolation, or public hosting.
