# v0.1.2 — 论文解析与检索地基升级 / Paper Ingestion & Retrieval Foundation

## 中文

### 版本定位

`v0.1.2` 是一次数据地基升级，重点解决论文内容在进入 RAG 前的可靠性问题：PDF 上下标静默丢失、固定长度切块跨章节、论文元数据写死、不同切块版本混入同一向量集合，以及检索效果缺少量化评测。

这个版本不会改变项目“本地优先、证据可定位、评分可复算、外发前明确同意”的原则。它为后续性能指标抽取、企业组合方案、院校论文工作台和论文谱系图提供更稳定的底层数据。

### 主要更新

#### 1. PDF 版面与上下标保真

- PDF 解析由普通纯文本提取升级为 span 级版面解析。
- 上标和下标显式保存为 `^{...}` 与 `_{...}`，减少 `cm^{-3}`、`10^{-7}`、`Sr^{2+}` 等科研表达被错误压平的风险。
- 保留原始 `plain_text`，便于对照审计。
- 自动识别重复页眉、页脚和页码；移除数量进入审计统计。
- 提取 PDF 书签目录、文本块坐标、图题和表题。
- 新增 `scripts/audit_pdf_layout.py`，默认只输出统计，不泄露论文正文。

#### 2. 章节感知的结构化切块

- 新增 `section_path`、`section_type` 和分类来源。
- 支持摘要、引言、相关工作、方法、实验、结果、讨论、结论、参考文献、致谢、附录、目录和未知章节。
- Chunk 不再跨越章节边界。
- 图题和表题成为独立 Chunk，方便后续关联论文图像、表格与技术路线。
- 没有 PDF 书签目录时采用保守回退；无法可靠判断的内容保留为 `unknown`，不强行制造错误标签。
- 切块版本升级为 `section_v2`。

#### 3. SQLite 论文目录与增量入库基础

- 新增本地 SQLite 论文目录。
- 使用 PDF 的 SHA-256 作为稳定论文标识和去重基础。
- 记录题名、作者、导师、年份、方向、页数、文件大小、来源类型、处理状态、解析版本、切块版本和授权备注。
- 支持导师、题名、作者、文件名、方向和处理状态查询。
- 增加 `discovered`、`parsed`、`indexed`、`failed` 等入库状态。
- Windows 默认将运行数据库放在用户目录兼容数据区，避免项目路径和商店版终端造成文件锁或权限问题。
- 新增 `scripts/sync_paper_catalog.py`。

原先写死在 Python 源码中的三篇论文元数据已迁移到可审查的 `config/paper_metadata.seed.json`。首次同步后，本地 SQLite 目录是运行时数据源。

#### 4. 版本化向量集合与后端接口

- 默认向量集合升级为 `paper_chunks_section_v2`。
- 旧集合不删除，新旧切块不会混写。
- 明确校验 Chroma 使用 Cosine 距离。
- Chunk 元数据增加论文 SHA-256 标识及解析/切块版本。
- 自动清理 Chroma 不支持的空元数据值。
- 新增后端无关的 `EvidenceIndex` 接口；以后评测 FAISS、Qdrant 等方案时，上层 Agent 无需整体重写。
- 增加显式关闭数据库句柄的能力，改善 Windows 临时文件与重复启动场景。

#### 5. 可重复的检索评测

- 新增人工相关性标注 `qrels` 规范。
- 新增 Recall@K、MRR@K 和 nDCG@K 计算。
- 新增本地 Dense 检索运行文件生成脚本。
- 每次检索方案升级都可以保存独立 run 文件，在同一批人工标注上做公平比较。
- 在真实人工标注完成前，项目只声明“评测能力已具备”，不宣称检索质量已经提高。

#### 6. 文档、测试与真实样本验收

- 新增带依赖关系和验收闸门的完整实施顺序。
- 更新中英文 README 与安装指南。
- 增加解析、切块、目录库、向量适配器和检索指标测试。
- 共 67 项离线测试通过。
- 在本机 3 篇授权测试论文上生成 894 个 `section_v2` Chunk，并使用 CUDA 完成新版向量集合重建。
- 本次验收没有调用 Moonshot，论文片段未外发。

详细本地统计见 `docs/evaluation/parser-section-v2-audit.md`。

### 从 v0.1.1 升级

更新代码后，在项目目录执行：

```powershell
conda activate industry_agent
python scripts/sync_paper_catalog.py
python src/retrieval/vector_store.py
python -m unittest discover -s tests -v
```

第二条命令会建立本地 SQLite 论文目录；第三条命令会生成新版 `paper_chunks_section_v2` 向量集合。旧向量集合会保留，但应用默认读取新版集合。

如果新增了自己的论文，请先把 PDF 放入 `data/raw/papers/`，再在 `config/paper_metadata.seed.json` 中补充文件名、作者、导师、年份和方向。不要把无权公开的论文、企业资料或 API Key 提交到 GitHub。

### 隐私与发布内容

本 Release 不包含：

- Moonshot API Key 或 `.env`；
- 原始论文 PDF；
- 本地 SQLite 目录数据库；
- Chroma 向量数据库；
- 企业需求、能力抽取结果、教师画像、匹配报告或 Agent 运行记录。

GitHub 自动提供的 ZIP 和 tar.gz 仅包含公开代码、合成示例、配置模板、测试和文档。

### 已知限制

- 真实检索质量仍需要人工制作 qrels 后才能量化。
- 无 PDF 书签目录的论文仍可能产生较多 `unknown` 章节。
- 当前尚未解析论文图片内容、复杂表格和扫描页 OCR。
- 性能指标本体、单位归一、BM25/RRF、重排、企业组合方案和谱系图将在后续版本实现。

## English

### Release scope

`v0.1.2` is a data-foundation release. It addresses reliability problems before paper evidence enters RAG: silently flattened scientific superscripts, fixed-size chunks crossing section boundaries, metadata hardcoded in Python, incompatible chunk versions sharing one vector collection, and the absence of quantitative retrieval evaluation.

The project remains local-first, traceable, reproducible, and consent-gated before any external API call. This foundation prepares the system for structured performance-metric extraction, enterprise solution composition, the academic paper workbench, and explainable paper lineage views.

### What changed

#### 1. Layout-aware and script-preserving PDF parsing

- PDF extraction now uses span-level layout information.
- Superscripts and subscripts are represented explicitly as `^{...}` and `_{...}`.
- Original `plain_text` is retained for comparison and auditing.
- Repeated headers, footers, and page numbers are detected conservatively and counted.
- PDF bookmarks, text-block coordinates, figure captions, and table captions are retained.
- `scripts/audit_pdf_layout.py` reports statistics without printing paper excerpts by default.

#### 2. Section-aware structured chunks

- Chunks now include `section_path`, `section_type`, and classification provenance.
- Supported types include abstract, introduction, related work, methods, experiments, results, discussion, conclusion, references, acknowledgements, appendices, contents, and unknown.
- Chunks do not cross section boundaries.
- Figure and table captions become standalone chunks.
- Papers without bookmarks use conservative fallback rules; uncertain content remains `unknown` instead of receiving a misleading label.
- The chunking pipeline version is now `section_v2`.

#### 3. SQLite paper catalog and incremental-ingestion foundation

- Added a local SQLite paper catalog.
- PDF SHA-256 is used as a stable paper identity and deduplication key.
- The catalog tracks title, authors, advisor, year, direction, page count, file size, source type, ingestion state, parser version, pipeline version, and authorization notes.
- Search supports advisor, title, author, filename, direction, and ingestion status.
- Added explicit ingestion states such as `discovered`, `parsed`, `indexed`, and `failed`.
- On Windows, runtime metadata uses a user-profile compatibility location to avoid path virtualization and file-lock problems.
- Added `scripts/sync_paper_catalog.py`.

The original Python-hardcoded metadata was moved to the reviewable `config/paper_metadata.seed.json`. After synchronization, the local SQLite catalog is the runtime source of truth.

#### 4. Versioned vector collections and index abstraction

- The default collection is now `paper_chunks_section_v2`.
- The previous collection is preserved, preventing old and new chunk formats from being mixed.
- Chroma's Cosine-distance configuration is validated explicitly.
- Chunk metadata includes paper identity and parser/pipeline versions.
- Unsupported null metadata values are removed before Chroma upserts.
- Added a backend-neutral `EvidenceIndex` protocol so alternative indexes can be benchmarked without rewriting every agent.
- Database handles can be closed explicitly, improving Windows cleanup and repeated-start behavior.

#### 5. Reproducible retrieval evaluation

- Added a human relevance-judgment (`qrels`) format.
- Added Recall@K, MRR@K, and nDCG@K metrics.
- Added a script that generates local Dense-retrieval run files.
- Future Dense, BM25, RRF, and reranking experiments can be compared on the same judgments.
- Until real human judgments exist, the project claims evaluation readiness—not improved retrieval quality.

#### 6. Documentation, tests, and local validation

- Added a dependency-ordered implementation sequence with acceptance gates.
- Updated both Chinese and English README and installation guides.
- Added parser, chunker, catalog, vector-adapter, and retrieval-metric tests.
- All 67 offline tests pass.
- The authorized local three-paper validation set produced 894 `section_v2` chunks, and the new collection was rebuilt with CUDA.
- No Moonshot request was made during this validation; no paper excerpts were sent externally.

See `docs/evaluation/parser-section-v2-audit.md` for the local audit summary.

### Upgrading from v0.1.1

After updating the repository, run:

```powershell
conda activate industry_agent
python scripts/sync_paper_catalog.py
python src/retrieval/vector_store.py
python -m unittest discover -s tests -v
```

The catalog command creates the local SQLite metadata database. The indexing command creates `paper_chunks_section_v2`. The old collection remains available, while the application reads the new version by default.

For your own papers, place authorized PDFs under `data/raw/papers/`, then add filename, author, advisor, year, and direction metadata to `config/paper_metadata.seed.json`. Do not commit restricted papers, enterprise information, or API credentials.

### Privacy and release contents

This Release does not contain:

- Moonshot API keys or `.env`;
- raw paper PDFs;
- the local SQLite catalog;
- the Chroma vector database;
- enterprise requests, extracted capabilities, teacher profiles, matching reports, or agent-run records.

GitHub's automatically generated ZIP and tar.gz archives contain only public code, synthetic examples, configuration templates, tests, and documentation.

### Known limitations

- Real retrieval quality still requires human-labeled qrels.
- Papers without PDF bookmarks may retain many `unknown` sections.
- Figure content, complex tables, and scanned-page OCR are not interpreted yet.
- Metric ontologies, unit normalization, BM25/RRF, reranking, enterprise solution composition, and lineage graphs remain future work.
