# FastAPI 产品网页改造说明

## 为什么新增产品网页

Streamlit 继续作为稳定的实验与管理入口。面向导师和企业的最终界面改用
FastAPI + 原生 HTML/CSS/JavaScript，以获得更自由的卡片、详情页、图片画廊、
长报告预览和流式任务交互。

新网页不会另建一套数据：它直接读取现有 SQLite 论文目录，并继续复用解析正文、
GPU 向量库、页码级 Chunk 和证据报告。

## 当前垂直切片

当前新增：

1. 论文成果卡片库；
2. 导师筛选、全文模糊搜索、处理状态筛选和分页；
3. 每篇卡片展示导师、题名、作者、年份、页数、标签、索引状态和报告状态；
4. 单篇论文完整详情页；
5. 本地证据底稿生成、预览、放大专注阅读和 Markdown 下载；
6. 本机原始 PDF 全页预览；
7. API 不向浏览器暴露论文绝对路径。
8. 按图号/表号和图注定位 PDF 原图区域，优先保留内嵌原图，并按页码与 `Fxx` 标签追溯；
9. 单篇 Kimi 结构化精读，将正文总结、原图/图注解读、原公式截图/转写/条件解读、方法路线、结果、局限和可转化技术资产合并为一份报告；
10. 所有非空结论必须引用实际存在的 `Exx/Fxx/Qxx` 标签，错误标签会被后端拒绝；
11. 同一次精读自动生成带证据标签的原生可编辑 `.drawio` 技术路线；
12. Kimi 结果按运行版本持久化，网页可预览并下载 Markdown、draw.io 或自带 `assets/` 的完整 ZIP 报告包。

本地证据底稿、图像提取、PDF 预览均不联网。Kimi 精读默认不执行；页面必须显示本篇
实际发送范围，并由用户勾选一次性同意后才调用 `.env` 中的 Moonshot 接口。当前单次上限为
10 个原文证据片段、6 张原公式区域和 4 张论文图像。API Key 不进入浏览器。

导出的 Markdown 使用 `assets/F01.png` / `assets/Q01.png` 这类相对路径，不再使用只有本地网页服务运行时才有效的 `/api/...` 地址。单独下载 `.md` 时需保留同级 `assets/` 目录；对外移交时建议直接下载完整 ZIP 报告包。

图版和公式在用户看到的报告中属于同一个“结构化精读”；后端仍拆成可重试步骤：先本地解析
正文与图注，再按需发送选定内容，最后本地校验标签、保存报告并生成 draw.io。这样某一步失败
不需要重新解析整篇 PDF。

## 启动

首次更新依赖后，双击：

```text
启动新版网页Demo.cmd
```

默认地址为 `http://127.0.0.1:8000`。原有 `启动网页Demo.cmd` 仍启动 Streamlit
稳定版，直到企业端和谱系版图全部迁移完成。

启动器会给每次打开的网址附加新的本地启动标识，并禁止缓存入口文件，避免浏览器复用
同一端口上曾经运行过的其他项目页面。如果看到旧页面请求 `/api/theses`，关闭旧标签页后
重新双击启动器即可；新版论文列表接口是 `/api/papers`。

## 覆盖范围

功能适用于 SQLite 目录中的全部论文，不写死导师或题名。当前真实目录有 2,920 篇论文；
其中累计 110 篇已完成正文解析和增量索引，因此只有这 110 篇目前具备生成结构化精读的
输入条件。其余论文须先按可恢复批次完成正文解析；不会在未经逐次同意的情况下把全库发往
Kimi。

## 后续顺序

1. 将剩余论文按可恢复批次解析和索引，并记录无文本/扫描件失败原因；
2. 增加精读任务队列、进度、失败重试和费用/Token 统计；
3. 为扫描页接入可选 OCR，为复杂表格增加独立结构化管线；
4. 在人工抽样集上验收图号定位、公式解释和 Kimi 结论准确率；
5. 生成版式一致的 PDF 报告，并把技术路线渲染图嵌入 PDF；
6. 迁移企业端闭环与谱系版图，最后替换默认启动入口。
