# 产学研 Agent 后续完整实施顺序

> 起始基线：v0.1.1；地基检查点：v0.1.2；制定日期：2026-09-01；依据：当前代码、产品路线图与《产学研Agent_v0.1_优化建议.md》。本文是工程执行顺序，不是功能愿望清单。

## 1. 决策摘要

项目继续坚持“证据可定位、评分可复算、未知项不伪造”。后续不能直接从页面原型跳到谱系图，也不能先把大量论文全部灌进现有向量库。正确顺序是：

**建立基线 → 修解析 → 修切块 → 建元数据底座 → 单方向指标化 → 提升检索 → 修需求与评分 → 跑通企业闭环 → 建院校工作台 → 生成报告与框图 → 做谱系 → 扩容部署。**

外部建议里“当前语料约 10GB、数千篇”等描述不是本项目当前事实，只作为未来容量目标。当前真实验收集仍是本地 3 篇论文，扩容前必须用抽样和评测结果决定存储迁移，不能凭猜测替换 Chroma。

## 3. 完整工作顺序与验收闸门

### 工作包 0：冻结安全与评测基线（进行中）

产物：离线单测、解析审计脚本、检索评测脚本、查询与 qrels 规范、数据不进 Git 的规则。

验收闸门：全部离线测试通过；真实数据/API Key 不在 Git；任何“提升”都有前后同集指标，未标注前只声明“工具可用”。

### 工作包 1：PDF 保真解析（第一版已完成）

产物：span 级版面解析、`^{}`/`_{}` 上下标表示、原始纯文本保留、书签目录、图表题识别、重复页眉页脚清理、解析版本号。

验收闸门：合成用例和真实抽样都能恢复 `cm^{-3}` 等表达；每篇记录上标数、移除边缘块数和异常页；扫描 PDF 明确标为待 OCR，不能静默输出空文。

### 工作包 2：章节感知切块（第一版已完成）

产物：`section_path` 与封闭的 `section_type`、图题/表题独立 Chunk、章节边界不混切、切块版本号。

验收闸门：TOC 论文按层级切分；无 TOC 论文允许 `unknown`，不得强行误分类；真实样本统计可审计。

### 工作包 3：论文目录与增量入库底座（第一版进行中）

产物：SQLite `papers` 目录、SHA-256 唯一标识、导师/题名模糊检索、方向和处理状态、解析/切块版本、向量索引接口、版本化 Chroma 集合。

验收闸门：同一 PDF 重复同步不产生重复论文；500 篇以上元数据不截断；旧版和新版 Chunk 不混库；中断后能识别已完成状态。

### 工作包 4：方向分流与小样本集（规则第一版已完成，人工复核待完成）

先选择一个方向（建议 X 射线/光电探测），人工确认论文归属，建立方向标签和最小金标集合。方向分类使用“规则/元数据优先，模型兜底”，且保留 `unclassified`。

验收闸门：每篇论文有方向来源与置信说明；抽样准确率经人工复核；不把未分类论文硬塞进某方向。

当前实现按“人工元数据 → 关键词规则 → 可选模型兜底 → `unclassified`”分流，并保存来源、置信度、命中词和待复核状态。本地 3 篇论文均命中已有人工元数据；这只能证明数据链路正确，不等同于方向分类准确率已经通过人工金标验收。

### 工作包 5：指标本体、单位与证据等级（第一版已完成）

本体分三层：跨方向通用指标、方向级指标、细分器件/工艺指标。先覆盖高频关键量，不追求一次全覆盖。每条指标包含规范名、原文值、归一值、单位、测试条件、页码/Chunk、`measured/reported/inferred` 证据等级。

验收闸门：同义词和单位换算有单测；无测试条件的数据不与有条件数据直接比较；推断值不能冒充实测值；指标记录必须能回到原文证据。

当前第一版本体覆盖 13 个高频指标，含方向范围、别名、规范单位和显式换算规则。每条记录保留原文指标名、点值/区间、原单位、规范值、测试条件、页码、章节、Chunk、原文摘录和证据等级；不同或缺失测试条件的记录不进入直接可比集合。

### 工作包 6：指标双通道抽取（确定性通道已完成，语义补充待实现）

先用正则/词典抓确定性数值，再让 Kimi 只补规则无法覆盖的上下文和实体关系，最后走现有校验器。图表指标先保留图题和页码，OCR/图像理解作为独立可选管线。

验收闸门：抽取准确率、单位归一准确率和证据定位准确率分别统计；错误不能只用一个总分掩盖。

当前只完成不联网的正则/词典确定性通道和结构校验器，没有调用 Kimi，也没有把规则结果标成推断事实。真实 3 篇本地论文共生成 160 条记录；详细边界和待人工复核项见 [指标底座 v1 验收记录](evaluation/metrics-foundation-v1-audit.md)。Kimi 只应在后续补充规则无法表达的上下文关系，并复用同一校验器。

### 工作包 7：检索升级与消融评测（工程第一版已完成，人工质量闸门待完成）

执行顺序：章节/方向/数值元数据过滤 → Dense 基线 → BM25 → RRF 融合 → 可选 CrossEncoder 重排。每加一层都保存独立 run 文件。

验收闸门：同一 qrels 上报告 Recall@5/10、MRR@5/10、nDCG@5/10、延迟和显存；指标下降则不合并。先在单方向小样本跑通，再扩展。

当前已实现统一的方向/章节/规范数值过滤、无外部依赖的中英混合 BM25、Dense/BM25 的 RRF 融合、可选 CrossEncoder 重排适配器，以及每种方法独立的 run、延迟、峰值显存和实验 manifest。提供 qrels 时，同一次命令会让全部方法使用同一份标注并分别保存 Recall/MRR/nDCG；没有 qrels 时，manifest 明确写入 `no_human_qrels`，不得声称检索质量提升。本地 3 篇/894 Chunk 已完成 CUDA 工程烟测，详见 [混合检索 v1 验收记录](evaluation/hybrid-retrieval-v1-audit.md)。

### 工作包 8：企业需求解析重构

企业原话拆为业务目标、对象/场景、必须指标、期望指标、约束、验收方法和未识别片段。规则处理明确数字和单位，Kimi 补充语义结构，用户确认后才生成方案。

验收闸门：原话逐段有去向；未读懂内容列入 `unparsed_fragments`；需求版本可追踪；任何补充假设都标记为“系统建议”，不能写成企业原话。

### 工作包 9：匹配评分校准

删除近乎恒定的“论文数量奖励”，覆盖度保留差距大小；未知项移出分母并单独报告；分数采用区间/档位而非虚假两位小数；Embedding 批处理缓存。

第一版只保留四维：技术适配、证据强度、工程成熟度、落地约束。权重和公式全部写入报告。

验收闸门：同一输入结果可复算；缺证据不会加分；人工排序与系统排序做 Top-K 对比；权重变更有版本。

### 工作包 10：企业端完整闭环（最高产品优先级）

固定流程：需求确认 → 技术问题拆解 → 候选模块 → 组合方案 → 技术路线 → 论文/教师证据 → 转化评估与落地计划。方案不是固定三个：只有满足证据覆盖闸门的方案才输出，否则输出“补证据/补实验”。

验收闸门：每个技术模块至少有一条证据或明确缺口；路线节点区分论文事实、工程推断和待验证项；报告含里程碑、验证方法、风险、设备/样品/人员依赖和停止条件。

**2026-09-02 P1 纵切已完成**：需求解析增加量化指标、测试条件、已有基础、排除路线和未解析片段；网页已实现“系统解析 → 逐项修改 → 保存不可覆盖版本 → 确认冻结 → 运行 GPU 检索”，原文和用户修改分别记录来源；论文按模块检索；方案数量由证据闸门决定；输出结构化路线、四维已知项评估、五项硬门槛、落地计划、Markdown 报告和原生 `.drawio`。指南示例和带 8 项量化指标的江西电缆公开榜单摘要均已完成本地 CUDA 验收。详见 [P1 企业端闭环验收记录](evaluation/p1-enterprise-loop-audit.md)。

### 工作包 11：院校端论文工作台

实现本地库/上传、导师与题名模糊搜索、论文列表、任务状态、论文精读、技术路线、转化分析、报告预览。上传使用哈希去重、大小/类型限制和失败状态。

验收闸门：大文件不一次性常驻 Session State；筛选变化不重复加载模型；上传失败可恢复；搜索结果与 SQLite 一致。

**2026-09-02 第一纵切已完成**：新增递归本地论文库同步、隐藏环境目录过滤、SHA-256 去重、文件来源缓存、PDF 上传安全检查、SQLite 分页检索以及多层论文标签。标签覆盖研究方向、材料、器件、方法、指标、应用、导师/作者/年份和人工标签；每条标签记录来源、置信度与“待确认/已确认/已驳回”状态，自动规则不会直接写成已确认事实。院校端已形成三栏工作台，可搜索导师/作者/题名/标签、分页选论文、编辑基础信息、审核标签、预览目录报告并下载 Markdown。精读、技术路线和转化分析在论文完成解析/索引前保持禁用，避免仅凭题名编造内容。真实目录的 2,921 个 PDF 已完成本地登记，详见 [院校论文库与标签 v1 验收记录](evaluation/academy-library-v1-audit.md)。

**2026-09-02 第二纵切已完成**：论文来源库改为“导师 → 论文”懒加载折叠列表；内部 `metadata_pending` 状态在页面显示为“已登记，待解析正文”；顶部工作区切换改用 Streamlit 原生导航；报告/PDF 支持全页预览。新增可恢复的小批次正文解析器，解析结果按论文 ID 原子写入压缩 JSON，SQLite 记录 `parsing/parsed/failed`，中断和失败均可恢复；正文规则标签带首次命中页码。首批 10 篇、734 页全部解析成功，新增 49 条正文标签，详见 [正文解析首批验收记录](evaluation/paper-parsing-batch-v1-audit.md)。

**2026-09-03 第三纵切已完成**：累计 110 篇、7,544 页完成正文解析和 GPU 增量索引，目录状态全部进入 `indexed`；新论文生成 30,568 个基于 SHA-256 的稳定 Chunk，加上原有 3 篇基线后，Chroma 共 113 篇、31,462 个 Chunk。新增 `indexing/index_failed` 可恢复状态、网页建库入口和 PDF 诊断降噪。院校端接入本地证据型精读第一版，自动生成抽取式一页导读，并按摘要、背景、方法、结果、结论五栏保留页码和 Chunk 引用；不向外部模型发送正文。详见 [100 篇扩容、GPU 索引与精读 v1 验收记录](evaluation/paper-indexing-reading-v1-audit.md)。

### 工作包 12：Markdown、PDF 与 draw.io 报告

统一报告对象先生成 Markdown，再生成 PDF；技术路线同时生成可编辑 `.drawio`，PDF 中嵌入渲染图。图中每个关键节点带来源编号，不能生成无证据的漂亮框图。

验收闸门：MD/PDF 内容一致；中文字体、分页、长表格和引用通过视觉检查；`.drawio` 可重新打开编辑；下载文件不含 API Key 和绝对本机路径。

### 工作包 13：论文谱系子图，再扩完整谱系

先做“当前需求相关证据子图”：需求—指标—能力—论文—教师。验证有用后再扩展为论文—作者—材料—工艺—性能—应用的全库图。边的类型、权重构成和证据来源必须可见。

验收闸门：不是仅凭单一向量相似度连边；阈值可调；孤立点可解释；点击节点能回到论文页码/Chunk。

### 工作包 14：批量扩容与存储基准

全量前按 10、100、500、1000 篇分批压测。记录解析吞吐、失败率、索引大小、P50/P95 查询延迟、召回指标、备份/恢复时间。达到本机瓶颈再依据数据迁移后端。

验收闸门：增量导入可重启；失败论文可重试；备份可恢复；后端迁移有双写或导出方案；全量入库最后执行。

### 工作包 15：安全、账号与部署

最后再做登录、角色权限、企业与院校数据隔离、审计日志、密钥托管、限流、队列任务和公网部署。单机版保持可用，不为云端复杂度牺牲本地路径。

验收闸门：最小权限；敏感数据默认不外发；外发前明确预览和同意；日志不记录密钥/全文；恢复与撤销路径经过演练。

## 4. 近期三个 Git 检查点

1. `foundation/parser-section-catalog`：解析、切块、目录库、版本化向量集合、审计和评测工具。
